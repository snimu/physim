# Maintaining the public documentation

The site is static HTML served from `docs/` by the existing GitHub Pages setup.
No JavaScript framework or package installation is needed to build it.

```sh
python3 scripts/build_docs.py
python3 scripts/check_docs.py
python3 -m http.server 8765 --bind 127.0.0.1 --directory docs
```

Edit `pages/index.html`, `partials/scoring.html`, `template.html`, and `site.css`, then rebuild.
The public narrative is one page following the author's PDF draft: Worlds,
Experiments, Evaluation, Preliminary Results, Discovering new worlds, What's next,
Get Involved, and Credit.
The vertical table of contents follows the introduction; its section links are
declared in `scripts/build_docs.py`.

The HTML fragments are the content source; `docs/*.html` is generated output.
Former chapter URLs redirect to their section in the single page. The recorded
anchors in `legacy-fragments.json` preserve old chapter links: retained sections
keep their anchor; removed details fall back to the corresponding main section.
Installation and reproduction details remain in `REPRODUCING.md` and package READMEs.

`worlds.json` retains downloadable preparation and coverage metadata. It is a documentation catalog, not a release manifest. The immutable genome
snapshot in `data/` records its published HF source. Its copy in `docs/data/` is checked
against that snapshot and the catalog hash, so a clean documentation build does not
require an environment source fixture. `registry.json` supplies the registry inventory.

The optional equation disclosures are generated by `scripts/world_equations.py`
from the published, hash-pinned genomes in `data/genomes/`; `data/equation-sources.json`
records their immutable HF locations. Each equation is written in the fields alone, with
constants combined exactly; the page rounds coefficients to four significant figures, and the
downloadable JSON keeps every stored digit. The numerical equation test checks the unrounded
expressions against the genomes.

The scoring formulas in `partials/scoring.html` are MathML. `site.css` sets them in a
bundled STIX Two Math subset (`docs/assets/fonts/`, with its license and subsetting recipe)
so radicals, sums and accents stretch on systems without a math font. The energy formula
has a second copy broken across two lines for phone widths; edit both copies together.

The BF figures and films that carry the narrative, and the p4g2_044 highlights film,
live in `docs/assets/bf-thread/`. `scripts/render_bf_thread.py` renders them from
hash-verified registry artifacts and native simulations, after reproducing the recorded
BF causal check bit for bit; that folder's README describes the display conventions and
`provenance.json` records inputs, runs, checks and encodings. Ordinary site builds use
the committed images and films.

BF/XV visual inputs are exact, small crops of recorded fields in `data/world-visuals.npz`.
Their JSON sidecar records original files, hashes, times, spatial windows, and the
common color scale. With NumPy and Matplotlib, regenerate the static figures using
`python scripts/render_world_visuals.py`. Ordinary site builds use the committed PNGs
and do not require those libraries or the historical simulation tree. The optional
`--capture-from outputs/eval-preparation-20260913` refreshes the crops deliberately.

`data/bf-case-study.json` preserves the original BF evidence: seven selected BF
rollouts with Prime Agent, per-case scores, native token accounting, source hashes,
and small trajectory slices. `python scripts/render_bf_case_study.py` renders the
figures with NumPy and Matplotlib; `--capture` deliberately refreshes evidence from
the saved September 19 campaigns. It reads submitted code as inert text and never
executes predictors or deserializes model pickles. The downloadable Python files in
`examples/case-study/` are for inspection; their fitted assets are not distributed.
Ordinary documentation builds use this bounded snapshot and the saved figures.

`results.json` retains a historical bounded snapshot of saved controls and two native
model-run profiles. Refresh deliberately with `python3 scripts/export_docs_evidence.py`;
this command reads local research evidence and never runs a model or simulator.
It includes every attempt from those two profiles, source hashes, and selected
settings, excluding transcripts and local artifact paths. Do not make ordinary
site builds depend on large research caches or run directories.
The historical selection rule shows one result per model in each profile: a scored attempt supersedes
unscored attempts, and the last recorded scored attempt is used regardless of
score improvement. Costs refer to that displayed attempt. All attempts and costs
remain in the snapshot; this display rule does not change the research ledger.

`examples/` is the source for downloadable code, request JSON, and the public
agent contract. Keep the contract aligned with `physim/data/agent_spec.txt` and check the
runnable predictor when changing the API. The zero example demonstrates shapes;
it is not a physical accuracy test.

`archive-map.json` records the 29 original pages and their archive destinations.
Historical HTML lives under `docs/archive/` with an archive banner. Existing media
remain in their original locations. The build creates small compatibility pages
at old URLs; in-site redirects preserve fragments. The build does not
regenerate the archived studies. There is no archive index or Reproduce chapter
on the current site. Their old URLs redirect to GitHub, as does the former registry
URL. The older `physim.results`, `physim.viz`, and
`physim.traces` generators default to the archive and refuse current-docs output
paths. They can also write to an explicit directory outside `docs/`.

Before public release, include the new documentation sources, examples, scripts,
archive pages, and source modules in the reviewed source set. The web build does
not implement the registry, package the native fixtures, or publish any data.
The public releases have passed clean-install and native checks for all three preparations; preserve those numerical identities when updating the site.

Apparatus diagrams are generated by `scripts/render_apparatus_figure.py` from native
sensor offsets. They are schematics, not simulated observations. The experiment
section documents `centered-pulse-v2`; the recorded BF case study used that apparatus with
the `interface-only-v2` prompt. Historical evidence retains its original apparatus
and harness conditions. Registry publication and installed-package config updates
are separate release steps, not side effects of building the documentation.

## Reward revision and fresh media

The historical BF snapshot and its original rewards are immutable inputs. The build
loads the standard-library-only runtime helper `physim/rewards.py` and writes
`docs/data/bf-reward-summary.json` with newly mapped rewards, K, and the original
snapshot hash. It does not rerun inference or overwrite the original scores.
Current prompts disclose K under `interface-only-v3-log-reward`; the historical
rollouts used `interface-only-v2` and are labeled as retrospectively remapped.

`data/reward-calibration.json` records native forecast scores against the unchanged
saved grading truths. Reproduce with the locked Physim environment:

```sh
python -m scripts.calibrate_reward --workers 8
```

The command writes resumable per-case arrays to `outputs/reward-calibration-20260926`.
Review the result before copying `calibration.json` into `data/reward-calibration.json`.
The build checks that its recommended K matches the runtime default.

Fresh field movies come from `python -m scripts.render_world_movies` with Matplotlib,
FFmpeg and the reference runtime installed. It uses the saved preparations, native
CPU stepper and recorded fresh seeds; no model inference. Full raw frame arrays are
cached under `outputs/world-movies-20260927`. Videos, posters and provenance JSON
are in `docs/assets/worlds/`. Selected fields use fixed color scales throughout
each film; all views are spatial crops of complete-domain simulations.

The focused films display selected fields in fixed windows. BF shows the moving
excitation and trail fields; XV overlays its two activators; p4 shows elongation
and splitting beside changing stripes, selected from a 900-time-unit continuation.
The shared encoder in `scripts/scientific_video.py` checks canvas dimensions and
compares decoded first/last MP4 frames against the rendered source images. This
guards against the rawvideo stride mismatch that distorted the earlier draft.

`python -m scripts.render_intro_examples` renders the early motion and binding
figures with larger type and stacked panels. The motion example is a fresh run
of the historical equations; the binding example preserves the original field
frames and uses the archived separation measurements. Each film has a source
record beside it under `docs/assets/worlds/early-*.json`.
